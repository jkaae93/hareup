# 화장실 아키텍처

- 요구사항: LITTER-01, LITTER-02. 책임: 일반 화장실·고양이·기준 사진 관리.
- 현재 상태: `FirestoreLitterBoxRepository`가 화장실 문서와 기준 사진을 선택된 그룹에 영구 저장한다. 앱은 Firebase 사진 분석 callable에 연결했지만 결과 정확도 검증 전까지 수치 표시 게이트를 비활성화한다. Preview는 메모리 저장소를 사용한다.

## 흐름과 계층

화면은 사용자 입력을 BLoC/Cubit에 전달하고 로딩·성공·빈 상태·실패를 렌더링한다. 일회성 이동과 메시지는 지속 상태와 분리한다. Domain은 엔티티·유스케이스·저장소 계약을 소유하고, data는 DTO·데이터 소스·저장소 구현을 제공한다. 앱 조립 계층이 구현을 주입한다.

## 데이터와 연동

- 의존성: 화장실 저장소, media, 사진 분석.
- JSON은 data 경계에서 DTO로 검증하고 도메인 모델로 변환한다. 공통 오류는 실패 타입으로 변환한다.
- 문서는 `groups/{groupId}/litterBoxes/{boxId}`, 사진은 `groups/{groupId}/litterBoxes/{boxId}/baselines/v{version}.jpg`에 둔다. Firestore/Storage 규칙에서 승인된 구성원 권한을 검증한다.
- 테스트에는 가짜 저장소와 고정 상태를 사용한다. 네트워크·플랫폼 플러그인을 Preview에서 호출하지 않는다.

## 검증 및 결정 대기

- 정상·빈 상태·실패·재시도와 권한 거부를 테스트한다. 입력·삭제·중복·그룹 격리는 해당 기능 구현 시 추가한다.
- 선행 결정: 추정량·지원 모래 및 삭제 정책. 실제 연동 전에 계약과 수용 기준을 구체화한다.
- 설계 변경 시 PRD 요구사항과 상태·인터페이스·테스트를 함께 갱신한다.

## 기능별 설계 상세

- 화면 흐름: 일반 화장실·고양이 등록 → 깨끗한 기준 사진 → 후속 사진 분석.
- 상태·계약: LitterBoxCubit: 생성·기준 변경·목록 조회; LitterBoxRepository와 기준 버전 계약.
- 필수 테스트: 자동화장실 거부, 일부 치수 입력, 기준 변경 기록 보존.
- 자동화장실 등록을 차단하며 부분 치수 입력도 허용한다. 사진 변경 시 기존 기준은 유지하고 새 버전과 시각을 기록한다. 분석 결과와 추정량은 제공하지 않는다.
- Firebase 구성: `FirestoreLitterBoxRepository(firestore:, storage:, groupId:)`; 저장소를 `LitterBoxCubit` 생성 시 전달한다. 기준 변경은 기존 사진을 남기고 새 버전을 추가한다.
