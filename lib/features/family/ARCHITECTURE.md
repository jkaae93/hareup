# 가족 아키텍처

- 요구사항: FAM-01. 책임: 초대 코드 생성·입력, 가입 승인, 가족 구성원 관리 및 접근 제어.
- 현재 상태: Firebase callable Functions와 Firestore/Storage 규칙, `FirebaseFamilyRepository`, 가족 생성·초대·가입 승인 대기·가족 선택 화면을 구현하고 앱 조립부에 연결했다. Emulator 통합 검증과 배포는 남아 있다.

## 흐름과 계층

화면은 사용자 입력을 BLoC/Cubit에 전달하고 로딩·성공·빈 상태·실패를 렌더링한다. 일회성 이동과 메시지는 지속 상태와 분리한다. Domain은 엔티티·유스케이스·저장소 계약을 소유하고, data는 DTO·데이터 소스·저장소 구현을 제공한다. 앱 조립 계층이 구현을 주입한다.

## 데이터와 연동

- 의존성: 가입 완료된 Firebase Auth 사용자, Firebase Functions callable API, Firestore.
- 스키마: `groups/{groupId}` 가족 정보; `groups/{groupId}/members/{uid}` 승인된 구성원(`uid`, `displayName`, `role`, `joinedAt`); `groups/{groupId}/joinRequests/{uid}` 가입 요청; `familyInviteCodes/{sha256(code)}` 초대 코드 해시. 초대 코드 원문은 발급 응답으로 한 번만 반환한다.
- Functions: `createFamily`, `listMyFamilies`, `getFamilyJoinStatus`, `getFamilyOverview`, `createFamilyInviteCode`, `requestFamilyJoin`, `approveFamilyJoinRequest`, `removeFamilyMember`. 가입 후 초대 코드를 입력해도 가입 요청만 생성한다. 승인 트랜잭션에서 구성원 문서를 만들며, 이 문서의 존재가 접근 권한을 뜻한다.
- JSON은 data 경계에서 DTO로 검증하고 도메인 모델로 변환한다. 공통 오류는 실패 타입으로 변환한다.
- 그룹의 관리자만 초대 코드 생성·가입 승인·삭제를 할 수 있다. 승인된 일반 구성원은 추가·수정할 수 있고 삭제는 할 수 없다.
- 가입 코드는 요청을 생성할 뿐 권한을 부여하지 않는다. 관리자가 승인한 뒤에만 구성원 문서와 그룹 접근 권한을 부여한다.
- 가족·구성원·요청 문서는 클라이언트 쓰기를 전부 거부한다. 승인 구성원은 그룹 반려동물·물그릇·화장실·기록 및 사진을 읽고 추가·수정할 수 있다. 삭제는 관리자만 가능하다. 가족 구성원 관리 작업은 Functions에서 매번 관리자 역할을 검증한다.
- 테스트에는 가짜 저장소와 고정 상태를 사용한다. 네트워크·플랫폼 플러그인을 Preview에서 호출하지 않는다.

## 검증 및 결정 대기

- 정상·빈 상태·실패·재시도와 권한 거부를 테스트한다. 입력·삭제·중복·그룹 격리는 해당 기능 구현 시 추가한다.
- 구현 가정(제품 결정 전 임시): 초대 코드는 7일 후 만료되며, 새 코드 발급 시 이전 코드는 즉시 무효화된다. 유효한 코드는 만료 또는 교체 전까지 여러 가입 요청에 재사용할 수 있다. 요청 중복은 사용자당 가족별 하나로 합친다.
- 미결정: 관리자 이전·탈퇴, 가족 데이터 보존·삭제 정책, 사용자가 여러 가족에 가입할 수 있는지, 가입 요청 거절 및 재요청 흐름, 미디어 보관 기간.
- 설계 변경 시 PRD 요구사항과 상태·인터페이스·테스트를 함께 갱신한다.

## 기능별 설계 상세

- 화면 흐름: 가입 완료 → 가족 선택 화면에서 가족 생성 또는 코드 입력 → 승인 대기 → 승인 후 서버의 내 가족 목록에서 선택 → 홈. 관리자는 가족 화면에서 코드를 만들고 가입 요청을 검토한다.
- 상태·계약: FamilyCubit은 조회·코드 생성·가입 요청·승인·제거를 담당한다. `FamilyRepository` 권한 플래그는 버튼 표시용이며 서버가 매 요청을 재검증한다.
- 필수 테스트: 코드 입력만으로 권한이 생기지 않는지, 비관리자 승인·삭제 거부, 구성원 추가·수정 허용, 다른 그룹 조회 차단, 제거 후 접근 회수를 검증한다.
- 응답 그룹 ID가 요청과 다르면 화면에 표시하지 않는다. 코드는 로그·분석 이벤트에 남기지 않는다.
- 잔여 작업: 앱 조립부에서 `FirebaseFamilyRepository`를 `FamilyAccessPage`와 `FamilyPage`에 주입하고, 선택된 승인 `groupId`만 홈에 전달한다. Emulator 보안 규칙 검증 및 실제 Firebase 설정 점검도 남았다. `createFamily`는 호출자에게 관리자 권한을 부여하므로 인증된 사용자만 호출하도록 Functions가 강제한다.
