# 사진 분석 아키텍처

- 요구사항: PHOTO-01, HEALTH-01. 책임: 기준·후속 사진 비교 및 결과 확인·수정.
- 현재 상태: 분석 요청·결과 계약, 검증 조건별 결과 차단, BLoC와 사진 비교 화면, Firebase Functions 사진 분석 callable 및 Flutter 어댑터를 구현했다. 배포와 실제 모델 호출 검증은 남아 있다.

## 흐름과 계층

화면은 사용자 입력을 BLoC/Cubit에 전달하고 로딩·성공·빈 상태·실패를 렌더링한다. 일회성 이동과 메시지는 지속 상태와 분리한다. Domain은 엔티티·유스케이스·저장소 계약을 소유하고, data는 DTO·데이터 소스·저장소 구현을 제공한다. 앱 조립 계층이 구현을 주입한다.

## 데이터와 연동

- 의존성: 사진 저장, Firebase Functions callable, 작업 식별자. Meta 키는 `META_MODEL_API` Secret으로 서버에서만 사용한다. Callable은 로그인 및 승인된 그룹 구성원을 확인하고 기준·후속 JPEG/PNG/WebP 이미지를 전달한다.
- JSON은 data 경계에서 DTO로 검증하고 도메인 모델로 변환한다. 공통 오류는 실패 타입으로 변환한다.
- 공유 데이터와 사진은 가족 그룹을 기준으로 분리하며 실제 서버에서 권한을 검증한다.
- 테스트에는 가짜 저장소와 고정 상태를 사용한다. 네트워크·플랫폼 플러그인을 Preview에서 호출하지 않는다.

## 검증 및 결정 대기

- 정상·빈 상태·실패·재시도와 권한 거부를 테스트한다. 입력·삭제·중복·그룹 격리는 해당 기능 구현 시 추가한다.
- 선행 결정: 분석 정확도와 건강 문구 전문가 검토. 실제 모델 수치 검증이 끝날 때까지 `AnalysisValidation` 게이트를 비활성화한다.
- 설계 변경 시 PRD 요구사항과 상태·인터페이스·테스트를 함께 갱신한다.

## 기능별 설계 상세

- 화면 흐름: 기준 확인 → 사진 선택·업로드 → 분석 → 결과 확인·수정 → 저장.
- 상태·계약: AnalysisCubit: 사진 선택·분석 시작·재시도·결과 확인; 원본 결과·사용자 수정·불확실성 상태 분리. AnalysisRepository: 작업 생성·조회·확정.
- 필수 테스트: 기준 부재·권한 거부·업로드 실패·불가 사진·중복 제출·검증되지 않은 수치 비노출.
- `AnalysisRuntime`으로 서비스·가족 ID·검증 정책을 주입하며 기본 앱은 미연결 서비스와 비활성 정책을 사용한다. 화장실에 연결된 고양이만 사용자 선택으로 기록할 수 있다.
- 앱은 Meta API 비밀키를 보관하거나 직접 호출하지 않는다. 서버 어댑터에서 지원 모델·이미지 입력·응답 형식·지역/계정 접근 가능성을 확인한 뒤 연결한다. Meta AI의 현재 개발자 페이지는 Meta Model API와 이미지·비디오 인식 모델을 안내하지만, 이것만으로 반려동물 관찰 결과의 정확도나 사용 가능 계약을 뜻하지 않는다.
- Meta 응답은 버전이 있는 DTO로 역직렬화하고 스키마·단위·범위·신뢰도 정책을 검증한다. 검증되지 않은 숫자는 도메인 결과로 변환하지 않는다.
- 동일 사진 재시도는 같은 요청 ID를 사용하며, 기준·후속 사진이 없으면 요청하지 않는다. 원본과 사용자 확인 횟수는 구분한다. 현재 시각은 촬영 시각이 아닌 사진 선택 시각이다.
- 잔여 작업: 활성 가족 선택을 포함한 앱 조립, Secret 등록·함수 배포, 실제 API 응답 확인, 사진 품질·분석 성능 검증, 건강 안내 전문가 검토 및 실기기 테스트.
