# 물그릇 아키텍처

- 요구사항: WATER-01, WATER-02. 책임: 그릇과 연결 동물·기준 사진 관리.
- 현재 상태: `FirestoreWaterBowlRepository`가 물그릇 문서와 기준 사진을 선택된 그룹에 영구 저장한다. 앱은 Firebase 사진 분석 callable에 연결했지만 결과 정확도 검증 전까지 수치 표시 게이트를 비활성화한다. Preview는 메모리 저장소를 사용한다.

## 흐름과 계층

화면은 사용자 입력을 BLoC/Cubit에 전달하고 로딩·성공·빈 상태·실패를 렌더링한다. 일회성 이동과 메시지는 지속 상태와 분리한다. Domain은 엔티티·유스케이스·저장소 계약을 소유하고, data는 DTO·데이터 소스·저장소 구현을 제공한다. 앱 조립 계층이 구현을 주입한다.

## 데이터와 연동

- 의존성: 물그릇 저장소, media, 사진 분석.
- JSON은 data 경계에서 DTO로 검증하고 도메인 모델로 변환한다. 공통 오류는 실패 타입으로 변환한다.
- 문서는 `groups/{groupId}/waterBowls/{bowlId}`, 사진은 `groups/{groupId}/waterBowls/{bowlId}/baselines/v{version}.jpg`에 둔다. Firestore/Storage 규칙에서 승인된 구성원 권한을 검증한다.
- 테스트에는 가짜 저장소와 고정 상태를 사용한다. 네트워크·플랫폼 플러그인을 Preview에서 호출하지 않는다.

## 검증 및 결정 대기

- 정상·빈 상태·실패·재시도와 권한 거부를 테스트한다. 입력·삭제·중복·그룹 격리는 해당 기능 구현 시 추가한다.
- 선행 결정: 그릇 형태 및 mL 검증. 실제 연동 전에 계약과 수용 기준을 구체화한다.
- 설계 변경 시 PRD 요구사항과 상태·인터페이스·테스트를 함께 갱신한다.

## 기능별 설계 상세

- 화면 흐름: 그릇 등록 → 반려동물 선택 → 앞·뒤·위 사진을 통한 초기 조건·수위 추정 → 사진 한 장으로 후속 수위 관찰.
- 상태·계약: WaterBowlCubit: 생성·기준 변경·목록 조회; WaterBowlRepository와 기준 버전 계약.
- 필수 테스트: 선택값 일부 입력, 기준 변경 시 과거 기록 보존, 공동 사용 결과.
- 등록 시 이름·반려동물·앞·뒤·위 사진은 필수이며 무게와 물의 양은 선택 입력한다. 초기 추정이 불확실하면 사진은 유지하고 초기 설정을 다시 시도한다. 모델은 사진으로 절대 용량을 확정하지 않는다.
- 수위 callable은 승인된 구성원을 확인하고 `waterLevelReadings`와 최신 수위를 트랜잭션으로 저장한다. 후속 분석은 저장된 조건과 사진 한 장을 사용한다. 수위가 불확실하거나 저장에 실패하면 최신 성공 기록을 바꾸지 않는다. 수치는 검증 설정에 따라 표시한다.
- Firebase 구성: `FirestoreWaterBowlRepository(firestore:, storage:, groupId:)`; 저장소를 `WaterBowlCubit` 생성 시 전달한다. 기존 사진은 기준 버전별로 보존한다.
