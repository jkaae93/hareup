# 설정 아키텍처

- 요구사항: AUTH-01. 책임: 로그아웃·버전·개인정보 및 지원 안내.
- 현재 상태: 버전 표시·선택 HTTPS 링크·인증 로그아웃과 Flutter Preview를 구현했다. 계정 삭제는 서버 계약이 없어 제공하지 않는다.

## 흐름과 계층

화면은 사용자 입력을 BLoC/Cubit에 전달하고 로딩·성공·빈 상태·실패를 렌더링한다. 일회성 이동과 메시지는 지속 상태와 분리한다. Domain은 엔티티·유스케이스·저장소 계약을 소유하고, data는 DTO·데이터 소스·저장소 구현을 제공한다. 앱 조립 계층이 구현을 주입한다.

## 데이터와 연동

- 의존성: 인증과 운영 콘텐츠.
- JSON은 data 경계에서 DTO로 검증하고 도메인 모델로 변환한다. 공통 오류는 실패 타입으로 변환한다.
- 공유 데이터와 사진은 가족 그룹을 기준으로 분리하며 실제 서버에서 권한을 검증한다.
- 테스트에는 가짜 저장소와 고정 상태를 사용한다. 네트워크·플랫폼 플러그인을 Preview에서 호출하지 않는다.

## 검증 및 결정 대기

- 정상·빈 상태·실패·재시도와 권한 거부를 테스트한다. 입력·삭제·중복·그룹 격리는 해당 기능 구현 시 추가한다.
- 선행 결정: 보관·삭제·지원 콘텐츠 및 알림 정책. 실제 연동 전에 계약과 수용 기준을 구체화한다.
- 설계 변경 시 PRD 요구사항과 상태·인터페이스·테스트를 함께 갱신한다.

## 기능별 설계 상세

- 화면 흐름: 설정 → 앱 버전·설정된 공지·개인정보·지원 링크·로그아웃.
- 상태·계약: SettingsCubit은 설정 정보를 불러오고, 설정된 HTTPS URL만 외부 앱으로 연다. 인증 흐름에서 전달한 로그아웃 동작은 확인 후 호출한다.
- 필수 검증: 잘못된 scheme·미등록 URL 차단, 플랫폼 버전 조회 실패 표시, Preview에서 외부 호출 방지.
- 잔여 작업: 계정 삭제와 로컬 캐시 정리를 서버 계약과 함께 설계한다.
